## Build and verify

Pages continues to serve the repository root at [the existing shortcut URL](https://austinevans33.github.io/dagger-caddie/). The retained manifest points at `./index.html`. The index, Yardage Book, Ghost and 19th Hole serve at that same origin and path prefix. The production runtime lives under `app/61f9e9de0a/` so a cached legacy document and a new document each load their own module graph. The original brand, manifest, baseline bag, production client identity and Firebase SDK origin are retained. The app uses the existing storage keys and format readers. No migration, origin redirect, service worker, or storage reset is added.

`python3 scripts/production-bundle.py --check .` reproduces and compares the versioned runtime and root pages to the exact staging source. Ryder's review-only record is removed from the public catalog. The source QA tree and the historical playtest config remain in Git and are excluded by the branch-root Pages build. The Pages gate checks the generated public tree for staging Firebase references, original launch assets and byte-for-byte release content. Production client Firebase configuration is copied from legacy main. Firestore rules, deployment settings and Functions stay at their prior revisions.

The PR workflow builds a Pages rehearsal artifact, runs the root browser tests under `/dagger-caddie/`, and runs the full pinned staging regression suite. The root tests use synthetic legacy data and block live Firebase requests. They cover both shortcut entry URLs, preserved member/score/round/bookmark/game data, QR encoding, same-origin Yardage Book and Ghost artwork, and Caddy handoff. A production Caddy OPTIONS response confirms that the current Pages origin is accepted. A signed-in live Caddy reply is part of acceptance.

## Before the merge

1. Check the green promotion workflow and its `PROMOTION_PR_HEAD.txt` against the current PR head. Confirm Pages Settings shows **Deploy from a branch → main → /(root)** and that no concurrent Pages release is pending.
2. On the actual iPhone, launch the currently installed shortcut, confirm the original URL and existing profile, and export the app backup before rehearsal. For candidate rehearsal use the workflow artifact at a private HTTPS origin, mounted at `/dagger-caddie/`. Create a test shortcut there, launch from Home Screen, refresh, close and reopen, and confirm the seal, scores and round persist. Use synthetic data in this separate origin. To certify the **existing installed shortcut with candidate bytes** before merge, the owner must provide a device-scoped, origin-preserving preview of the workflow artifact. A separate-origin rehearsal verifies standalone Safari behavior and cannot certify the installed production shortcut or its stored data. Keep the release gate open until that rehearsal is signed off.
3. On two physical iPhones, open the pinned Firebase staging preview above. Start a disposable Money Room on phone A, scan the host QR from phone B, enter a hole on A, check sync and participant permissions on B, reload both, then check BBB, finish/archive and confirm the Ledger. Verify Yardage Book → Ghost → Caddy for Pudding Ridge and Oak Island. Record the device, iOS version, preview SHA and results. Repeat read-only production account, known-room recovery and signed-in Caddy verification in the origin-preserving rehearsal with owner-provided test accounts and a designated test room. Keep staging and production room IDs separate.
4. Record the passing results on the PR, compare its exact base/head to the tested versions, then squash-merge the promotion as one rollback unit. Keep the original URL and Pages publishing source.

## After publication and rollback

Wait for the Pages deployment for the merge commit to finish. Run `python3 scripts/production-bundle.py --verify-live` to compare the public shortcut root, manifest, icons, runtime and data with the candidate. Launch from the actual installed iPhone shortcut and confirm old data and round access. Record the Pages deployment SHA and link.

If a release regression blocks the shortcut, storage, or Money Room, revert the single squash promotion commit through a rollback PR to main. Leave Firebase and browser storage intact. Wait for the rollback commit's Pages deployment, then run `python3 scripts/production-bundle.py --verify-rollback` from the promotion checkout to compare the live files to the baseline. Reopen the shortcut after the Pages cache refreshes. The released runtime's versioned paths make a cached pre-promotion document independent from the new module graph.
